# The verify page

A static page that re-runs a seal's checks in the reader's browser:
content hash, wallet signature, live AgentBook registration, chain
anchor, and the human-approval tier, each reported separately with
named failure states, and the check time always shown. It never
takes the seal's word for anything, and a check that cannot run is
reported as incomplete, never as a verdict.

## Serving

Serve the repository root from any static host; the page lives at
`verify/` and loads the library from `../src/` directly. There is
no build step. The page's two `@noble` dependencies are vendored
under `verify/vendor/` (refresh them after `npm install` with
`node scripts/vendor-deps.mjs`), so the page does not depend on a
CDN.

## Sample

`verify/demo-fixture.json` is a sample seal made with the published
Hardhat test key 0, generated by `scripts/generate-demo-fixture.mjs`.
Loading it (the page's sample button, or `?sample=1`) runs the
checks with the registration answered from a recorded fixture for a
synthetic test human, labelled as such on the page; content and
signature checks run for real. Live mode reads the AgentBook
registry on World Chain through the public RPC endpoint in
`browser-providers.js` (configurable there), and pins the
endpoint's chain identity before trusting any answer.

## Files

- `index.html`: the page (markup, styling, rendering).
- `browser-providers.js`: the AgentBook and anchor providers over
  plain JSON-RPC. They run identically in Node, and
  `tests/verify-page.test.js` drives them with a stubbed RPC,
  including the failure-honesty cases.
- `demo-fixture.json`: the labelled sample seal.
